# Northstar Markets · 美国市场交易产品

> **当前公网版本是模拟交易版。** 价格展示可能来自行情 API，也可能来自 SIM 数据；ETF、时间合约和事件预测订单都不是券商订单。PTS/USD 是虚拟记账余额，USDT 充值按钮不会验证链上交易，提现审核也不会发起转账。请勿向平台转入真实资产，也不要在当前 KYC 页面提交真实证件。

## 当前实现

- React + Vite H5 前台与独立后台路由，Express API，Supabase Auth；当前仓库没有 iOS/Android 原生应用工程。
- Supabase 持久化成员资料、模拟订单、后台配置、KYC 申请元数据、模拟 USDT 流水，以及 PTS/USD 模拟账户和账本；服务端密钥仅用于服务端访问，浏览器不应持有服务角色密钥。
- 行情支持 Alpaca Basic IEX 快照适配器；配置服务端 API Key 后，在本地开发环境可读取有限范围的单所行情。公网生产还需明确开启展示授权标记；这不是全市场 SIP 行情，也不代表取得了商业再分发或结算授权。
- ETF 模块当前是虚拟下单和后台逐笔模拟结算，没有券商订单号、真实成交、持仓托管或清算。
- 时间合约只使用下单时冻结的 SIM 曲线计算模拟结果；交易所同步的 YES/NO 概率是参考行情，不是本平台可交易或可结算的实盘价格源。
- 事件预测使用本地 CPMM 概率模型。后台人工结算目前只是模拟记录，不构成交易所事件合约结算。
- USDT 页面属于演示资金流程。链上监听、交易确认、地址归属验证、反洗钱筛查和真实提现广播尚未启用。
- KYC 当前是后台审核队列；没有正式身份核验服务，也不接收证件文件。

## 本地运行

```bash
npm install
npm run dev
```

- 前台：<http://127.0.0.1:5173/>
- 后台：<http://127.0.0.1:5173/admin>
- 本地默认管理员密钥：`local-demo-admin`（只允许本地开发；公网必须配置高强度 `ADMIN_REVIEW_KEY`）
- 构建：`npm run build`
- 自动化测试：`npm test`

环境变量样例见 `.env.example`。不要把生产密钥提交到 GitHub，也不要把服务端 Supabase 密钥放进 `VITE_` 变量。
Alpaca 行情密钥只配置到本地 `.env` 或 Vercel 服务端环境变量；不要粘贴到聊天或前端代码。公网展示需要先获得数据方授权，再设置 `ALPACA_PUBLIC_DISPLAY_AUTHORIZED=true`。

部署步骤和当前交付边界见 [产品交付手册](docs/PRODUCT-HANDOFF.md)。新环境需要在 Vercel 配置 `ADMIN_REVIEW_KEY`、`SUPABASE_URL` 与 `SUPABASE_SECRET_KEY`，并按顺序应用 Supabase 数据库迁移。

## 美国真实证券交易发布路线

本项目不会自行托管客户证券或资金。计划采用**持牌券商合作**，先接普通股票/ETF 的账户、资金、订单、成交、持仓和对账接口；模拟余额和后台手动输赢逻辑不能迁移到真实订单。美国券商/交易平台可能承担受监管活动，SEC 的券商注册指南说明了常见注册与成员要求；产品上线前需要由美国证券律师结合最终业务结构审查，而不能仅凭软件实现判断资格。[SEC：Broker-Dealer Registration Guide](https://www.sec.gov/divisions/marketreg/bdguide.htm)

可先做商业尽调的券商基础设施候选：

- [Alpaca Broker API](https://docs.alpaca.markets/us/v1.1/docs/about-broker-api)：官方文档描述账户开立、资金和交易 API；正式环境需先取得相应合作及上线批准。[账户开立流程](https://docs.alpaca.markets/us/v1.1/docs/account-opening)
- [DriveWealth Developer API](https://developer.drivewealth.com/apis/docs/intro)：官方文档描述嵌入式券商基础设施，包括开户、资金、交易、托管、清算与监管报告能力；仍需其商业审核和合同。

这些是候选方，不表示 Northstar 已获准接入。连接器须只在服务端运行；将客户的 Supabase `personal_id` 映射到合作券商账户 ID；客户账户状态、可用购买力、订单、成交和持仓以券商事件/API 为准；重试通过幂等客户端订单 ID 保护；建立券商流水与内部只读账务的日终对账。只有拿到合作方沙盒访问及产品批准后，才能开始真实接口联调；生产密钥必须通过 Vercel 环境变量或密钥管理服务注入。

### 产品边界

- **股票与普通 ETF：** 第一阶段经获批券商合作接口交易。市场数据的显示授权与下单执行授权分开核验。
- **1–100 倍杠杆：** 当前 ETF 模块只是模拟参数，不能直接升级为真实杠杆。必须先由券商确认具体产品、适当性、购买力、保证金、强平和客户披露规则，并经法律审查。
- **秒合约与事件合约：** 不是普通股票/ETF 订单。美国的二元期权和事件合约有独立监管与交易场所要求；CFTC 明确提示基于证券价格的二元期权可能属于证券，商品类二元期权则需要满足相应交易场所要求。[CFTC：Binary Options Fraud](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/fraudadv_binaryoptions.html) 当前功能不能面向真实客户资金上线。
- **USDT 资金：** 不属于券商股票账户的自动充值。须另行确定合规托管/支付结构、许可范围、链上风控和法律意见；在此之前只保留明确标记的测试流程。

## 上线阻塞项

1. 选定并签约美国持牌券商合作方，取得沙盒/生产权限和书面产品范围批准。
2. 由美国证券律师确认发行实体、客户招揽、代理/介绍关系、州要求、杠杆产品和事件合约的可行范围。
3. 完成券商账户开户/KYC/AML、资金流、客户协议、风险披露、交易确认和投诉处理流程。
4. 实现券商订单生命周期、部分成交/撤单/拒单、持仓和活动同步，以及幂等、重试、对账和审计。
5. 选择获准的美国市场数据方案，验证实时/延迟数据权利及应用展示许可。
6. 做安全、隐私、依赖、灾备、渗透与业务连续性审查；完成沙盒验收和运营演练。
7. 真实杠杆、时间/事件合约和 USDT 入金分别通过对应合作方与法律审核后，再决定是否纳入首发。

完成这些外部合作与审核前，公网只可作为明确标注的模拟产品使用，不应宣传为可实盘交易平台。
